# 部署与可观测实施规格

本轮目标：可重复启动、可观察异步积压、失败隔离与重放、可备份及恢复。现有本机端口保持可用；容器环境采用独立项目名与端口，验证后再切换。

## 交付边界

社区、审核、worker 独立进程；前端生产静态文件由反向代理提供。镜像绑定提交版本。MySQL 持久化卷，迁移作为发布前独立步骤。指标覆盖 HTTP、数据库连接池、待审时长、Outbox 等待与死信。日志统一 JSON，保留请求或事件关联号；不记录凭证和用户正文。

Outbox 失败必须回滚业务副作用；失败次数与下次执行时间持久化，指数退避，达到上限进入死信；其他事件可继续处理。人工重放必须记录操作人与理由，且保留失败历史。

发布需要构建测试、固定镜像、迁移、健康检查、业务冒烟和版本记录。应用回滚要求数据库向后兼容，不自动执行破坏性数据库降级。

## 验收

1. 原有数据库业务回归通过。
2. 毒消息不阻塞后续正常事件；重启保留退避/死信状态；重复消费无重复通知。
3. 数据库故障不能被指标表示为零积压；指标查询错误必须显式失败。
4. 容器配置可校验，完整栈实际启动才可标记运行验收完成。
5. 备份完整性校验，并在隔离数据库恢复核查。
6. 告警故障注入可触发并恢复；真实外部通知渠道由用户指定后接通。

告警接收渠道已选定飞书机器人，先实现 Alertmanager → 签名适配器 → 飞书的接口与错误语义；密钥仅本机配置。尚无云账号、域名与机器人凭证，因此不声明云端发布验收或真实外部告警送达。

## 本轮决策与剩余边界

本机保留内嵌 worker 以保持开发服务可用；容器拆出独立 worker 并提供内部采集端口。基础栈本地接收告警，飞书使用独立 Compose 覆盖配置启用，避免未提供机器人凭证时伪装成外部通道已接通。基础阈值暂定接口 5xx 比例 >5%、P95 >1 秒、Outbox 等待 >120 秒；它们是初始告警配置，不是压测验证后的容量或 SLO。

本轮只完成应用与业务指标、JSON 日志以及监控部署文件；宿主机、容器和 MySQL 服务端 exporter、集中日志检索和链路追踪仍待实现。验收结果逐项见 ../verification/infrastructure-acceptance.md。

事件处理按当前内容状态收敛：延迟下架事件不得删除当前已重新发布的关注流记录；延迟发布事件不得恢复已隐藏内容；重复发布同步当前发布时间且不重复插入。缺少通知接收人或正文的内部消息按失败进入重试，不能静默标记成功。
