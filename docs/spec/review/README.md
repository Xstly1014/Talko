# 人工审核服务：本轮交付规格

状态：本轮实现及本机验收完成，公网试运营门禁仍未完成。社区继续开放游客浏览；全部用户生成的图文、机会、评论与资料变更先审核后公开。

## 服务边界

- community：社区 API :8080 / Web :5173。
- review：人员审核 API :8081 / Web :5174，独立启动、部署与会话；社区不提供跳转审核后台的产品入口。
- 共享 MySQL 中的不可变内容版本与事务领域逻辑，暂不拆数据库，避免首期引入分布式事务。
- 开发邮件 :1025 / :8025，仅本机；生产邮件与外部模型本轮不接入。

## 人员与权限

公开注册只面向社区；审核人员由受信任管理员通过本地命令开通。reviewer 可读取并领取内容任务，risk 额外处理举报与申诉，admin 额外查看审计。会话 Cookie 名、有效期与 API 路径隔离；每次鉴权读取人员停用状态。禁止以作者身份审核自己的内容；申诉复核禁止原审核员与作者处理。

## 审核任务

待审 / 已处理 / 已撤回，按图文机会、评论、资料过滤。领取保护期 15 分钟，可续期；处理接口校验人员与保护期。过期或其他人员领取返回冲突；最终领域事务再次校验内容状态与具体版本，旧版本不可发布。通过与驳回均填写 2–400 字依据；广告由人员分类并展示于公开内容，不把所有涉及报酬的信息自动标记为广告。

## 治理闭环

1. 资料先生成变更版本；公开资料维持当前已通过版本。新变更替代待审旧变更，通知与记录可追溯。
2. 图文举报绑定提交举报时的公开版本；评论正文不可变。后台同时展示举报理由、原始证据与当前对象状态。处置可维持现状或下架，记录处理人员与依据，通知举报人与被处置作者。
3. 申诉针对已驳回审核决定。复核可维持原决定，或将仍有效的原版本重新加入待审队列；不直接跳过审核发布。原审核决定保留，新任务独立编号，原作者或原审核员不能复核。已删除、下架、替换或过期版本不得重开。
4. 用户可在自己的举报、评论举报、申诉与消息中查看处理结果；其他用户不可访问。

## 界面规则

白色背景、浅蓝色强调，左侧服务内导航。列表具备加载、错误、空状态、筛选与分页；正文换行保留，图片可放大核查，机会结构化展示主体、地点、报酬、结算、有效期、联系渠道及风险提示。后台不得显示虚构处理量或自动通过占位能力。

## 必验收

- 社区会话不能访问审核 API；reviewer 不得通过直接请求执行 risk/admin 操作。
- 两人领取冲突、未领取决定、领取过期、任务撤回、资料被替换均拒绝错误变更。
- 资料公开隔离、广告标识持久化、评论举报去重与下架后公开读取过滤。
- 举报证据绑定版本；申诉重开保留原结论，重新进入人工审核，过期或替换版本拒绝重开。
- 使用真实 MySQL 集成测试；前端类型检查与生产构建；浏览器登录、领取与决策联调。

## 上线仍需后续门禁

生产人员账户管理与 MFA/身份提供商、敏感行为风险控制、完整安全测试、外部对象存储、可观测与告警、任务补偿、备份恢复、隐私治理与云端发布流程。当前本机可运行不代表允许公网试运营。
