# 质量、运维与验收

## 安全

服务端对象级鉴权、限流、上传类型及大小校验、CSRF 防护（若使用 cookie）、安全会话、XSS 输出转义、参数化 SQL；敏感信息脱敏，凭证通过环境或密钥系统注入。学生认证材料最小化收集、加密存储、授权访问和到期删除；试运营前明确责任人、举报入口及应急下架。

## 验证

- 业务：草稿→审核→发布→举报→下架；机会到期和修改重审；申诉与注销。
- 一致性：提交重复、审核与撤回竞争、旧版本回调、Outbox 重复投递、下架后缓存命中、关注变化、恢复重放。
- 安全：越权、非法上传、脚本注入、恶意请求频率、敏感信息泄露；人工审核不可用时禁止公开。
- 前端：页面主要流程、响应式、键盘操作、加载/空/失败/冲突；跨浏览器验证。
- 运维：数据库备份和异机恢复、发布回滚、缓存失效、消息积压及告警演练；记录环境、时间和结果。

## 指标与日志

请求成功率及延迟、发布/审核成功率、待审时长、Outbox 最老消息、消费积压、上传失败、数据库连接及慢查询；日志关联 request_id、trace_id、post_id、revision_id，禁止记录令牌与敏感材料。SLO、告警阈值、保留周期基于测量后决定。

## 交付顺序

1. 确认本规格及试运营范围；建立仓库、环境和 CI，完成基础身份与数据库迁移。
2. 完成资料、媒体、草稿、提交及模拟审核，覆盖核心规则与测试。
3. 对接真实审核、发现/关注流、互动、举报及申诉；建立运营与风控责任。
4. 完成安全检查、监控告警、备份恢复和发布回滚演练，再邀请少量用户。

## 不满足上线条件

仅有模拟审核、无责任人、无隐私说明或无法恢复数据时不得邀请真实用户；单机并非高可用。具体的地区适用要求、成本与法律审查由实际运营条件决定。


## 容量目标澄清

真实试运营规模约 100 用户。10 万用户是拟模拟的压测规模，而非并发数或当前生产事实。实施前定义注册数据量、日活比例、同时在线、请求速率、读写比例、数据分布、时长、环境规格和性能指标；分别测试真实试用容量与扩展压力，记录成本、瓶颈和可复现脚本。不得将压测结果描述为真实线上用户规模。
