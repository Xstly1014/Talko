# 总体决策

## 产品与目标

面向受邀大学生的图文社区，提供校园经验、就业实习、升学考试、出国及兼职家教信息。首期完成可审核、可举报、可下架、可运营的闭环，不承诺机会真实性或担保交易。不提供私信、支付、交易撮合、视频及算法推荐。

## 交付边界

校园社区作为一个独立前端部署单元，配套一个 Go 社区后端部署单元；用户、内容、关系、Feed、媒体、通知在后端模块化单体内，逻辑边界清晰。审核、运营、风控后台独立部署，通过受鉴权的 API/事件协作；不在首版为每个模块拆微服务。首个交付要能本地运行，跨系统依赖通过明确的模拟适配器验证，真实用户试用前接入真实审核治理能力。

## 建议技术栈（待确认）

- 后端：Go，标准 net/http 或轻量路由器；分层为 transport、application、domain、infrastructure；依赖注入显式组装。版本选择以实施时稳定版本及生命周期验证为准。
- 前端：React + TypeScript + Vite，路由与数据请求分层，采用成熟组件库并建立设计令牌。前后端独立构建；服务端鉴权为最终边界。
- 数据：MySQL 为事实源；Redis 用于会话、限流和可重建缓存；S3 兼容对象存储存图片。数据库迁移版本化。
- 事件：MySQL 事务性 Outbox；第一阶段可由同进程后台任务投递，跨服务接入后选消息队列；不声称恰好一次。
- 开发：WSL 作为 Linux 开发环境，Docker Compose 启动本地依赖；代码、环境变量模板、迁移和运行说明纳入仓库，密钥不入库。
- 可观测：结构化日志、Prometheus 指标、OpenTelemetry 链路；先确保关键路径可定位，再接入集中平台。

## 部署与演进

浏览器 → HTTPS 反向代理 → 社区前端 / Go API → MySQL、Redis、对象存储；后台任务消费 Outbox。开发、测试、生产隔离；单机方案有单点，必须异机备份、恢复演练和明确停机预期。服务拆分依据独立扩容、团队责任和故障隔离的实测需求，不按页面拆分。

## 架构约束

数据库事务内写业务数据和 Outbox；外部调用不放进数据库事务。所有公开内容读取校验当前状态及可见性；跨系统消息至少一次，消费者幂等。系统时钟 UTC 存储、界面按用户时区显示。所有规模、SLO、费用作为测量后确认的目标，不使用虚构线上指标。


## 已确认的方向（2026-10-29）

- 允许访客浏览公开内容；产品面向大学生，但不限制非大学生使用，不需要学生身份认证。
- 注册使用邮箱验证，不要求学校邮箱。真实试运营预计约 100 用户；压测可能模拟 10 万用户。10 万指模拟用户规模，不等于 10 万并发或线上实际用户数；并发、行为比例和通过阈值须另行设计并测量。
- 家教、兼职允许个人发布，采用大模型辅助审核结合人工审核；涉及金钱的内容卡片展示“信息来源未核实 / 可能涉及广告，请谨慎甄别”的醒目标识。具体展示文案按内容类型确定，不能将所有内容都断言为广告。
- 达到上线标准后再准备云服务器和域名；当前以 WSL 开发和本地环境为主。框架按场景评估，不预设强制框架。
- 深入业务线之一为风控；另一条建议选择内容生命周期与分发，理由见业务规格。实施前确认。
