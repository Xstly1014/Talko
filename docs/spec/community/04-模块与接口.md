# 模块、数据与接口契约

## 约定

前缀 /api/v1；JSON UTF-8；时间 RFC 3339 UTC；ID 使用字符串；分页采用不透明 cursor + limit（默认 20，上限 50）。统一错误 {code,message,request_id,details}；400 参数、401 未登录、403 无权、404 不存在或不可见、409 状态冲突、429 限流、5xx 服务失败。写请求支持 Idempotency-Key，作用域为用户 + 路由，按请求摘要检测冲突；过期策略待定。状态更新携带 version，冲突返回 409 并提示刷新。

## 模块与接口草案

| 模块 | 职责与数据 | 接口（均以 /api/v1 为前缀） |
|---|---|---|
| 身份 | User、Session、Invitation；密码安全散列、会话撤销 | POST /auth/register、/auth/login、/auth/logout、/auth/recovery；GET /me |
| 个人资料 | Profile：昵称、简介、头像 media_id | GET /users/{id}；PATCH /me/profile；GET /users/{id}/posts |
| 媒体 | Media：所属用户、对象键、类型、大小、检测状态 | POST /media/uploads 创建受限上传；POST /media/{id}/complete；GET /media/{id} |
| 内容 | Post、Revision、Draft、Opportunity | POST /posts；GET /posts/{id}；PATCH /posts/{id}/draft；POST /posts/{id}/submit、/withdraw、/delete；GET /me/posts |
| 审核 | ReviewTask、Decision，版本绑定 | GET /posts/{id}/review；内部 POST /internal/review-decisions（服务身份、签名或 mTLS，幂等） |
| 关系 | Follow，唯一 follower_id + followee_id | PUT /users/{id}/follow；DELETE /users/{id}/follow；GET /users/{id}/followers、/following |
| 流与搜索 | FeedItem 为索引，非权限事实 | GET /feed/discover、/feed/following、/search、/topics、/topics/{id}/posts |
| 互动 | Like、Favorite、Comment | PUT/DELETE /posts/{id}/like、/favorite；GET/POST /posts/{id}/comments；DELETE /comments/{id} |
| 通知 | Notification、read_at，事件去重 | GET /notifications；GET /notifications/{id}；POST /notifications/{id}/read |
| 举报申诉 | Report、Appeal，关联对象及决定 | POST /reports、/appeals；GET /me/reports、/me/appeals |
| 账号权利 | 身份验证、注销申请、数据导出 | POST /me/deletion-requests、/me/data-exports；GET 对应申请状态 |

## 关键请求与约束

- 创建草稿：POST /posts，{type,title,body,media_ids,topic_ids,opportunity?} → 201 {id,revision_id,version,status}；机会字段须在提交时完整校验。
- 提交审核：POST /posts/{id}/submit，{revision_id,version} → 202 {task_id,status}；并发撤回通过版本条件更新解决。
- 审核回传：{event_id,task_id,post_id,revision_id,decision,reason,decided_at}；验证来源、任务、版本和决策，重复事件去重；写状态和 Outbox 同事务。
- 上传：服务端限制 MIME、大小、数量和对象归属；客户端不得指定任意对象路径；完成后检测，内容审核通过前不可公开。
- 评论：POST /posts/{id}/comments {body} → 待审核状态；不可直接公开。

## 事件草案

信封包含 event_id、event_type、schema_version、aggregate_id、occurred_at、trace_id 和 payload；事件包括 PostSubmitted、ReviewDecided、PostPublished、PostHidden、ReportSubmitted。Outbox 至少一次投递，消费者记录 event_id 幂等；死信、重试、对账及敏感字段最小化。外部审核系统不可用时保持待审，禁止降级为自动通过。

## 数据约束

post 与 revision 分离，revision 内容不可变；公开查询根据 post 当前发布版本和状态判定。关系、点赞、收藏建立联合唯一索引；审计保存操作人、动作、原因、时间及关联版本。具体字段、索引和 API 示例在实现前以 OpenAPI 和迁移文件细化并评审。


## 风控契约补充

RiskAssessment 包含 assessment_id、revision_id、模型/规则版本、风险类别、建议结论、执行状态、人工决策与审计关联；模型调用通过适配器隔离，禁止在请求中发送不必要的个人数据。检测状态包含 pending、processing、requires_manual、decided、failed；超时及失败进入人工队列。机会字段包含 compensation、settlement、expiry、publisher_type、risk_disclosure 与 advertising_disclosure；金额和联系方式的展示遵循隐私与平台规则。公开接口返回明确的风险提示字段，客户端不得仅靠关键词自行推断。
