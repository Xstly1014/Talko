# 待讨论决策

以下均为建议，未视为用户确认：

1. **首批用户与范围**：建议受邀大学生、小规模单地区试用；是否允许访客浏览？预期用户数和月预算是多少？
2. **身份方式**：建议邀请码 + 邮箱登录，学生认证作为可选标识；是否必须学校邮箱或人工认证？这会改变准入与隐私成本。
3. **机会信息准入**：建议仅邀请经人工核验的发布者，个人经验分享与招聘机会分开；是否允许个人直接发布家教和兼职？谁负责审核及投诉？
4. **首期评论**：建议支持审核后公开的基础评论，不开放私信；是否首期需要评论？
5. **部署方式**：建议 WSL + Compose 本地开发，试运营采用云主机和托管备份；是否已有服务器、域名、对象存储及预算？
6. **技术选型**：建议 Go + React/TypeScript + MySQL + Redis + S3，单体模块化 + Outbox；是否有必须使用的框架或基础组件？
7. **数据策略**：审核 SLA、账号注销冷静期、素材保留期、审核证据访问范围和备份 RPO/RTO 需要结合运营能力确认，不能直接套用示例值。
8. **业务展示重点**：建议深入内容版本、审核和关注流；是否还希望机会核验成为主要业务亮点？

确认后应更新规格版本与决策记录，再进入 OpenAPI、数据库设计及实现；本文不将模拟数据或预期成果写成真实经验。
